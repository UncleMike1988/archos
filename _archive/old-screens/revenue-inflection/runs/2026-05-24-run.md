## Methodology note

EdgarTools `search_filings_full_text` returned zero results for compound
queries with phrase-quote AND chained on inflection terms ("more than
doubled" AND "AI infrastructure" returned 0). Single-phrase queries
worked. The boolean AND with phrase quotes appears to be unreliable for
this type of language search.

Productive queries:
- `"AI data center"` — 25 hits (most usable for triage)
- `"AI infrastructure"` — 76 hits (high-volume; lots of incidental mentions)
- `"significant inflection" AND "data center"` — 1 hit (VECO; surgical)
- `"record revenue" AND "data center"` — 10 hits (mostly false positives — "record revenue" matches verb form "record [verb] revenue [noun]")

Web search (Option C) surfaced WYFI, INOD, AAOI directly. Used as cross-
reference against EdgarTools. The web search was more productive at name
discovery than the EdgarTools queries — file structure searches generated
high signal-to-noise but discovery searches via finance media were more
selective.

## Refinement notes

### Query effectiveness
- **EdgarTools phrase-AND chains are unreliable.** `"phrase X" AND "phrase Y"` returned 0 hits on multiple queries that should have had at least some matches. Either the boolean AND across phrase quotes is buggy or the index doesn't support that combination. **Switch to single-phrase queries and post-filter.**
- **"AI data center"** is the most discriminating single phrase. 25 hits, ~30% actionable triage rate.
- **"AI infrastructure"** is too noisy — 76 hits, most incidental references in supply-chain risk sections.
- **"significant inflection" AND "data center"** worked perfectly for the one hit it returned (VECO). Surgical phrases are productive when the language is distinctive enough.

### Signal-to-noise
- 76 surfaced via EdgarTools queries → 4 sub-$5B sub-cap candidates → 1 borderline pass (WYFI) → 0 strict passes
- The first run validates that the screen is well-tuned for specificity (no false positives on the strict criterion) but the strict criterion is so tight that most quarters will have zero or one hit
- This is **the correct calibration** — the bellwether sweep also produces zero-hit weeks regularly (per INSIGHTS.md). Tight specificity is a feature

### Tooling friction
- **WebFetch returns 403 on SEC.gov URLs.** Switch to EdgarTools `financial_statements` and `filing_section` for filing content reads. (Used `company_brief` and web search to triangulate this run.)
- **No XBRL revenue at quarterly granularity is exposed by `financial_statements` for VECO** (returned TTM only) — the revenue tag was null in the response. Need to test `filing_section` on the 10-Q directly to pull MD&A revenue tables.
- **Web search produces faster name discovery** than EdgarTools filing-language search for this screen. Reverse the order in v2: lead with web search (Option C), then verify via EdgarTools (Option A/B).

### What to change for next run
1. Drop multi-phrase boolean AND queries; use single-phrase queries and triage manually.
2. Lead with Option C (web search) and use EdgarTools for primary-source verification rather than discovery.
3. Add a "segment-level inflection" pass — companies with a disclosed AI-infra segment >40% YoY inside a flat parent. This catches the SANM and PENG patterns.
4. Add the two-degree supplier dimension — VECO is downstream of NVDA but upstream of the CPO/optical chain. The revenue inflection screen needs a "process equipment" hook to catch tool vendors when their order book inflects ahead of customer revenue.
